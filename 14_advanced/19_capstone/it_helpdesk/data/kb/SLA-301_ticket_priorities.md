# SLA-301: Ticket Priorities and Response Times

| Priority | When to use it | First response | Assigned group |
|---|---|---|---|
| **P1 - Critical** | Security incidents; a service is down for everyone | 1 hour | IT Security / Major Incident team |
| **P2 - High** | One employee cannot work at all (cannot sign in, laptop dead, VPN fails on both gateways) | 4 hours | Service Desk L2 |
| **P3 - Medium** | Something is broken but there is a workaround | 1 business day | Service Desk L1 |
| **P4 - Low** | How-to questions, hardware refresh requests, minor annoyances | 3 business days | Service Desk L1 |

## Rules for the helpdesk assistant

- Try self-help from the knowledge base first. Raise a ticket only when the
  self-help steps did not work or cannot work (for example a hardware fault).
- Do not raise a ticket for a problem already shown on the service status page
  as a known outage or planned maintenance.
- Before creating a new ticket, check whether the employee already has an open
  ticket for the same problem - if so, give them that ticket number instead.
- Every ticket must have a one-line summary that names the system and the symptom.
